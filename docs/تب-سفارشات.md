# تب سفارشات — قرارداد فعلی فرانت‌اند

این سند نسخهٔ به‌روز جریان فرانت‌اند است. قرارداد کامل endpointها در `docs/API_CONTRACT.md` مرجع اصلی است.

## جریان فعلی پرداخت

1. کاربر سبد خرید را در `benamacademyCart` مرور می‌کند. این داده فقط پیش‌نویس UX است و قیمت یا موجودی قابل اعتماد نیست.
2. فرم تسویه‌حساب مشخصات خریدار، شناسه محصولات، تعداد و کد تخفیف را مستقیماً به `POST /commerce/payment` ارسال می‌کند.
3. سرور قیمت محصولات، تخفیف، موجودی و مبلغ نهایی را از منبع معتبر خودش محاسبه می‌کند.
4. سرور سفارش را ایجاد می‌کند، درگاه بانکی را فراخوانی می‌کند و `redirectUrl` معتبر HTTPS برمی‌گرداند.
5. مرورگر فقط به `redirectUrl` منتقل می‌شود. فرانت‌اند اطلاعات کارت بانکی، CVV2، تاریخ انقضا، رمز پویا یا کپچا دریافت نمی‌کند.
6. درگاه نتیجه را به callback سرور برمی‌گرداند و سرور تراکنش را از درگاه استعلام و تأیید می‌کند.
7. صفحه رسید فقط شناسه سفارش را از URL می‌گیرد و جزئیات و وضعیت را از `GET /commerce/orders/:id` می‌خواند. پارامتر URL مثل `status=success` منبع اعتبار نیست.
8. مجوز دسترسی به فایل‌ها از `POST /commerce/entitlements` دریافت می‌شود و فقط از سفارش‌های پرداخت‌شده ساخته می‌شود.

## قراردادهای لازم

### ایجاد پرداخت

`POST /commerce/payment`

```json
{
  "buyer": { "name": "نام خریدار", "email": "email@example.test", "phone": "09xxxxxxxxx" },
  "items": [{ "id": "product-id", "qty": 1 }],
  "couponCode": null
}
```

پاسخ موفق:

```json
{ "success": true, "orderId": "order-id", "redirectUrl": "https://gateway.example/transaction" }
```

فرانت‌اند مبلغ یا قیمت واحد را ارسال نمی‌کند. حتی اگر در نسخه‌های قدیمی payload مبلغی وجود داشت، سرور نباید به آن اعتماد کند.

### خواندن سفارش و مجوزها

- `GET /commerce/orders/:id`: فقط سفارش متعلق به کاربر احراز هویت‌شده را برگرداند.
- `POST /commerce/entitlements`: فهرست شناسه محصولات قابل دسترسی را از سفارش‌های تأییدشده برگرداند.

## نکات امنیتی

- فرانت‌اند هیچ پرداختی را شبیه‌سازی نمی‌کند و گزینهٔ تست پرداخت ناموفق ندارد.
- فرانت‌اند سفارش موفق یا مجوز دانلود را در `localStorage` ثبت نمی‌کند.
- callback درگاه، مبلغ، وضعیت تراکنش و مالکیت سفارش باید سمت سرور اعتبارسنجی شوند.
- فایل‌های پولی باید از endpoint امن یا لینک امضاشده با انقضا تحویل شوند؛ لینک ثابت عمومی کافی نیست.
